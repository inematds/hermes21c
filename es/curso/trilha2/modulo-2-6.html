📈 Mejora con el uso — memoria muscular

La idea central: cuanto más usas Hermes y le das feedback continuo, mejor se vuelve. Como un músculo que desarrolla memoria, aprende tus patrones, perfecciona skills y anticipa lo que sueles pedir. La mejora es acumulativa.

🔁 El ciclo de mejora

  • •Usa → el agente ejecuta
  • •Da feedback → "esto quedó bien", "prefiero así"
  • •Itera → la próxima vez sale mejor

💡 Consejo práctico

El feedback breve y específico vale más que un elogio genérico. "Acorta los resúmenes a 3 viñetas" entrena mejor la memoria muscular que "está genial".

2

🎯 Skills listas y las tuyas

Hermes tiene skills — rutas guardadas de "cómo hacer" una tarea. Algunas vienen listas y mejoran con el uso; otras las construyes tú (ve agentskills.io). Una skill es una receta reutilizable: enseña el «cómo» una vez y luego puedes reutilizarla siempre.

📊 Skill = el "cómo"

Piensa en una skill como una macro inteligente: describes el procedimiento una vez y el agente lo repite con calidad. Cuanto más se usa, más afinada queda.

3

🏛️ Panteón — agregar personas

O Pantheon es donde creas personas: especialistas dedicados. Cada persona (por ejemplo, «el Alquimista») tiene job, descripción, system prompt y, crucialmente, un modelo propio. Es como formar un equipo de especialistas, cada uno con el cerebro adecuado.

Definición de una persona (ilustrativo)

persona: "o Alquimista"
job: transformar ideias soltas em planos
descrição: criativo, faz conexões inesperadas
system_prompt: "Você é um sintetizador..."
modelo: claude-opus (alto impacto)

💡 Consejo práctico

Crea pocas personas bien definidas en lugar de muchas imprecisas. Una persona con un job claro + el modelo adecuado ofrece mucho más que diez personas genéricas.

4

🚗 No uses Einstein para lavar el auto

La regla de oro del ahorro: modelos caros solo para tareas de alto impacto. No tiene sentido usar un modelo de razonamiento premium ("Einstein") para una tarea trivial ("lavar el auto"). En autopilot, usa un modelo barato; para lo importante, el modelo potente.

✓ El modelo adecuado para cada tarea

  • ✓Razonamiento difícil → Opus
  • ✓Volumen / rutina → GPT / DeepSeek
  • ✓Autopilot → modelo económico

✗ Desperdicio

  • ✗Opus para clasificar correos
  • ✗Modelo premium en un ciclo de rutina
  • ✗El mismo cerebro para todo

📊 Se conecta con la Trilha 1

Es la estrategia multi-brain: "para un martillo, todo es un clavo". Cada persona/skill apunta al modelo más adecuado: ahorra dinero sin perder calidad donde importa.

5

🔬 Skill "deep research" — delega en varios modelos

Ejemplo poderoso: la skill deep research. Pides «investiga cuál es el mejor país para vivir» y ella: inicia un subagente, usa DeepSeek V4 + GPT en bucle para la investigación de volumen, con Opus 4.7 revisando la calidad. Cada modelo en la función que mejor desempeña.

1

Levanta un subagente

Contexto fresco dedicado a la investigación, sin contaminar la conversación principal.

2

DeepSeek V4 + GPT en bucle

Los modelos de volumen recopilan y procesan datos en iteraciones: son económicos y rápidos.

3

Opus 4.7 revisa

El modelo potente interviene solo en la revisión final, para garantizar la calidad donde importa.

💡 Por qué esto es elegante

Combina skills + subagentes + multi-brain. Opus, que es caro, solo se encarga de lo que necesita buen criterio; el modelo barato hace el trabajo pesado. Los subagentes son tema de la Trilha 3.

6

⏹️ /stop — interrumpir la tarea

Skills y personas dan mucho poder de acción automática — así que necesitas un freno. El comando /stop interrumpe de inmediato la tarea en curso. El control es parte de la capacidad: poder empezar no basta, necesitas poder parar.

Uso de /stop (ilustrativo)

› hermes: rodando skill deep-research (turno 7/20)…
você: /stop
› hermes: tarefa interrompida. 6 fontes coletadas até aqui.

📊 Cuándo usar /stop

  • Cuando te des cuenta de que pediste lo equivocado
  • Cuando una skill está consumiendo demasiados tokens
  • Cuando quieres redirigir al agente antes de que termine
