🔌 MCPs

"El manual de instrucciones." MCP = Model Context Protocol. Si la API es el cableado expuesto, el MCP es el manual que lo acompaña: un control remoto universal que conecta Hermes con casi todo y consume muchos menos tokens.

🔌 Qué es MCP

MCP significa Model Context Protocol. Es un estándar que empaqueta una herramienta de una manera que el modelo entiende, incluyendo qué acciones existen, qué hace cada una y cómo invocarlas. En lugar de que Hermes adivine cómo usar la herramienta, recibe el «manual» listo.

💡 En una frase

MCP es una forma estandarizada de conectar herramientas a Hermes. Al agregar el MCP, el agente ya conoce todos los "botones" de esa herramienta.

2

🔧 La API es el cableado; MCP, el manual

La mejor analogía: la API es el cableado eléctrico expuesto: funciona, pero tienes que saber exactamente dónde va cada cable. El MCP es el manual/paquete de instrucciones que rodea ese cableado: un control remoto universal con los botones ya etiquetados.

🔧 API (cableado expuesto)

  • Necesitas descubrir los endpoints
  • El modelo «prueba» cómo llamar
  • Cada uso vuelve a explicar la herramienta

📘 MCP (manual listo)

  • Enumera las acciones disponibles
  • El modelo ya conoce los «botones»
  • Uso estandarizado y repetible

📊 Control remoto universal

Un único protocolo conecta Hermes con prácticamente todo. En vez de aprender el "cableado" de cada servicio, lee el manual y opera, como si apuntaras un control universal a cualquier aparato.

3

⚡ Por qué MCP en vez de solo una API key — eficiente en tokens

La gran ventaja técnica: MCP es mucho más token-efficient. El modelo lee el manual una vez y ya conoce todas las acciones (redactar un email, crear un evento, buscar un archivo), sin tener que volver a explicar la herramienta en cada llamada. Menos tokens, menos costo, más consistencia.

✗ Solo API key (verboso)

  • ✗Vuelve a explicar la herramienta cada vez
  • ✗Revisión repetida = más tokens
  • ✗Mayor probabilidad de errores de uso

✓ MCP (eficiente)

  • ✓Lee el manual una vez
  • ✓Ya conoce todos los botones
  • ✓Uso estandarizado y económico

💡 Se conecta con el presupuesto

Como ~73% de cada request es overhead fijo (Trilha 3, módulo 3.5), ahorrar tokens repetidos con MCP tiene un impacto real en el costo a lo largo del tiempo.

4

📓 Granola MCP — ejemplo sencillo

Granola MCP conecta Hermes con tus reuniones. Es plug-and-play: agregas el MCP por nombre y lo autorizas en el navegador mediante OAuth, sin guardar una clave. A partir de ahí, preguntar sobre reuniones "simplemente funciona".

1

Indica el nombre del MCP

Dices "agregar Granola MCP" — no necesitas una clave ni configuración manual.

2

Autoriza en el navegador (OAuth)

Abre una pestaña, inicia sesión y haz clic en «Allow». No hay ninguna clave que pegar en ningún sitio.

3

Listo para usar

"¿Cuál fue mi última reunión?" Ya tiene la respuesta: el MCP expone las acciones automáticamente.

🔗 OAuth vs token

Cuando el MCP ofrece OAuth (como Granola), prefierelo: no hay ninguna clave que pueda filtrarse. Cuando requiere un token (tema siguiente), guárdalo en el env, nunca en el chat.

5

⚙️ Zapier MCP — miles de apps

Zapier MCP es la navaja suiza de las navajas suizas: tú levanta servidores que se conectan a apps, agrega las tools que quieras (p. ej., "leer correo"), genera un token y lo agrega mediante una variable de entorno. Esto abre miles de integraciones de una vez.

Cómo agregar el token de Zapier MCP (ilustrativo)

# gere o token no painel do Zapier, depois NO TERMINAL:
export ZAPIER_MCP_TOKEN="SEU_TOKEN_AQUI"

# NUNCA cole o token no chat — ele é indexado e vai pros backups
# o MCP lê a variável de ambiente

⚠️ Seguridad del token (igual que la API key)

El token de MCP es una credencial como cualquier otra: nunca en el chat, siempre en el env mediante terminal. Todo lo que entra en el chat se guarda/indexa — y se copia en backups diarios.

6

🛡️ Deja "enviar email" para más adelante

Al configurar un MCP de correo electrónico, agrega tools de lectura ("leer correo", "redactar un borrador"), pero retén "enviar/responder email" hasta confiar en el flujo. Algunas personas ya tuvieron problemas con agentes que enviaron correos indebidos. Es el principio del menor acceso en la práctica.

✓ Habilita primero (bajo riesgo)

  • ✓Leer correo
  • ✓Redactar / crear (sin enviar)
  • ✓Buscar y resumir

✗ Déjalo para después (alto riesgo)

  • ✗Enviar email
  • ✗Responder automáticamente
  • ✗Cualquier acción irreversible

💡 Regla práctica

Habilita tools según el nivel de riesgo: primero lectura, luego escritura reversible y, por último, acciones irreversibles cuando confíes. El acceso mínimo te protege a ti y a quienes reciben los mensajes.
