🏛️ Pantheon de personas

O Pantheon mostra suas personas de forma visual dentro do OS — cada uma com seu job, system prompt e modelo. Ver tudo num lugar facilita escolher quem usa o quê e garante que você não está rodando o modelo caro numa tarefa trivial.

📊 O que cada persona carrega

  • Job — para que ela serve (pesquisa, escrita, suporte).
  • System prompt — como ela se comporta.
  • Modelo — o cérebro atribuído (caro só nas de alto impacto).
3

🗄️ Memory vault

O memory vault é um cofre que recupera qualquer email, reunião ou nota — e você pode conectar fontes externas como o NotebookLM. É a memória da Trilha 2 elevada a um componente central do OS, acessível num olhar.

Diagrama ilustrativo · fontes plugáveis convergindo num cofre central

4

📈 Mission control

No mission control você vê, num olhar: conexões disponíveis, modelo em uso, memória, gasto de IA, ganhos com skills e uso em tempo real. Operar sem painel é voar às cegas — especialmente depois do que você aprendeu sobre custo no módulo 3.5.

💡 Dica prática

As métricas ao vivo do mission control são sua primeira linha de defesa contra um cron descontrolado: se o gasto disparar, você vê na hora.

5

💭 Dreaming improvements

O OS não é estático: ele "sonha" melhorias à noite e volta com sugestões proativas no dia seguinte. Combinado com heartbeat e memória, o sistema evolui sozinho — propõe novos crons, ajustes de persona, otimizações de custo.

✓ O que o "sonho" gera

  • ✓Sugestões de automação que repetem seu padrão.
  • ✓Ajustes de persona conforme seu uso.
  • ✓Ideias de economia de tokens.

✗ O que ele não deve fazer sozinho

  • ✗Executar ações irreversíveis sem aprovação (volta ao 3.1).
  • ✗Ligar poderes novos sem você confirmar.
  • ✗Gastar acima do teto definido.
6

💾 Backup no GitHub

Seu OS é valioso demais para morrer com o hardware. Conecte-o ao GitHub para um backup diário do Hermes inteiro — personas, memória, configs. Trocou de PC ou perdeu a máquina? Restaura tudo. (Cuidado: como visto no 3.1, isso reforça por que segredos nunca podem estar no chat — eles iriam para o backup.)

🏗️ Montando seu OS, passo a passo

O OS não nasce pronto — você o constrói por camadas. Uma ordem que funciona bem, da base ao topo:

1

Base: soul + memória

Dê identidade ao agente e deixe a memória compor por ~2 semanas.

2

Conexões com menor acesso

Ligue 2-3 integrações em modo leitura primeiro (módulo 3.1).

3

Automação + teto

Um cron de briefing e um teto de gasto. Observe o mission control.

4

Backup + Claude Code

Ligue o backup no GitHub e conecte o Claude Code (módulo 3.7).

✓ Construir bem

  • ✓Camada por camada, observando cada uma.
  • ✓Backup ligado antes de depender do OS.
  • ✓Teto de gasto desde o primeiro cron.

✗ Erros comuns

  • ✗Ligar tudo no primeiro dia, sem observar.
  • ✗Confiar no OS sem backup configurado.
  • ✗Crons demais antes de entender o custo.

💡 Dica prática

Trate o OS como uma casa: fundação (soul + memória) antes das paredes (conexões), e o sistema de alarme (backup + teto) antes de morar nele.
