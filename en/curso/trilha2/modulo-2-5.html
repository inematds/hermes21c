🔌 MCPs

"The instruction manual." MCP = Model Context Protocol. If an API is exposed wiring, MCP is the manual around it—a universal remote that connects Hermes to almost anything while using far fewer tokens.

🔌 What Is MCP

MCP means Model Context ProtocolIt’s a standard that packages a tool in a way the model understands — including what actions are available, what each one does, and how to call them. Instead of Hermes guessing how to use the tool, it gets the ready-made "manual."

💡 In a nutshell

MCP is a standardized way to plug tools into Hermes. Add an MCP, and the agent already knows all the "buttons" for that tool.

2

🔧 API is the wiring, MCP is the manual

The best analogy: the API is exposed wiring — it works, but you need to know exactly where each wire goes. The MCP is the manual/instruction package around that wiring: a universal remote control with the buttons already labeled.

🔧 API (exposed wiring)

  • You need to discover the endpoints
  • The model “tests” how to call
  • Each use requires re-explaining the tool

📘 MCP (Ready-to-Use Manual)

  • Lists the available actions
  • The model already knows the “buttons”
  • Standardized, repeatable usage

📊 Universal remote control

A single protocol connects Hermes to practically everything. Instead of learning each service’s “wiring,” it reads the manual and operates — like pointing a universal remote at any device.

3

⚡ Why MCP instead of just an API key — token-efficient

The key technical advantage: MCP is much more token-efficientThe model reads the manual once and already knows all the actions (draft an email, create an event, search for a file)—without having to re-explain the tool with every call. Fewer tokens, lower cost, more consistency.

✗ API key only (verbose)

  • ✗Explains the tool all over again each time
  • ✗Repeated checks = more tokens
  • ✗Higher chance of user error

✓ MCP (efficient)

  • ✓Reads the manual once
  • ✓Already knows all the buttons
  • ✓Standardized, low-cost usage

💡 Connects to budget

Since ~73% of each request is fixed overhead (Trail 3, module 3.5), saving repeated tokens with MCP has a real impact on costs over time.

4

📓 Granola MCP — Simple Example

The Granola MCP connects Hermes to your meetings. It plug-and-play: you add the MCP by name and authorize it in the browser via OAuth—no key to store. From then on, asking about meetings "just works".

1

Provide the MCP name

You say "add Granola MCP" — no key or manual setup needed.

2

Authorize in the browser (OAuth)

Opens a tab; you log in and click “Allow.” No key to paste anywhere.

3

Ready to use

"What was my last meeting?" It already has the answer—the MCP exposes actions automatically.

🔗 OAuth vs. Token

When the MCP offers OAuth (like Granola), prefer it: there's no key to leak. When it requires a token (next topic), store it in the env — never in chat.

5

⚙️ Zapier MCP — thousands of apps

Zapier MCP is the Swiss Army knife of Swiss Army knives: you starts servers that connect to apps, add whatever tools you want (e.g., "read email"), generates a token and adds it via an environment variable. This opens up thousands of integrations at once.

Adding the Zapier MCP token (illustrative)

# gere o token no painel do Zapier, depois NO TERMINAL:
export ZAPIER_MCP_TOKEN="SEU_TOKEN_AQUI"

# NUNCA cole o token no chat — ele é indexado e vai pros backups
# o MCP lê a variável de ambiente

⚠️ Token security (same as an API key)

The MCP token is a credential like any other: never in chat, always in the env via terminal. Everything entered in the chat is saved/indexed — and copied to daily backups.

6

🛡️ Hold off on “send email” for now

When setting up an email MCP, add tools for read-only ("read email," "draft"), but hold "send/reply to email" until you trust the workflow. People have already been burned by agents sending inappropriate emails. This is the principle of least privilege in practice.

✓ Release first (low risk)

  • ✓Read email
  • ✓Draft / create (without sending)
  • ✓Search and summarize

✗ Hold off for now (high risk)

  • ✗Send email
  • ✗Reply automatically
  • ✗Any irreversible action

💡 Rule of thumb

Enable tools by risk level: read first, reversible writes next, and irreversible actions only once you trust them. Least access protects you and the people on the receiving end.
